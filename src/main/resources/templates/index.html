Reel Tiles Count ChancesiPer-reel probability distribution for the number of visible tiles per reel. Each row is 6 comma-separated percentage values corresponding to tile counts 2, 3, 4, 5, 6, 7 — i.e. the 1st value is the chance a reel shows 2 tiles, the 2nd is for 3 tiles, …, the 6th is for 7 tiles. Values must sum to 100. Leave a row blank to use a uniform distribution.
Default: 35, 35, 20, 5, 3, 2 — biased toward 2–3 tiles, tapering off sharply at higher counts. Filled automatically by the ✦ button above.

Generate — Configuration Fields
Strategy Determines the algorithm used to place tiles on each reel strip.

SHUFFLE — Stochastic placement algorithm. Behaviour depends on whether restrictions are defined:
  With restrictions: For each position on the reel, a stack height is sampled from the weighted distribution defined by stackSizes / stackChances. A symbol is then chosen at random from the remaining tile pool and placed as a consecutive run of that height. Before committing the placement, the algorithm checks that the chosen symbol does not violate the minDistance constraint — i.e. the same symbol must not have appeared within the last N positions. If the constraint is violated, a different symbol is tried. If no valid symbol can be placed after exhausting all candidates, the attempt is abandoned and the entire reel is regenerated from scratch (up to 8 retries). If all retries fail, the reel is emitted as [].
  Without restrictions: All tiles are expanded into a flat list and shuffled uniformly at random (Fisher-Yates shuffle). Every tile is placed individually (stack size 1 for all). No distance constraints are applied.

FLAT — Deterministic sequential placement. All copies of symbol 1 are placed first, then all of symbol 2, and so on in ascending symbol order. No randomisation, no stacking, restrictions are ignored.
History size Maximum number of past generation results kept per session. Allowed values: 1, 3, 5, 10, 20. When the limit is reduced, the oldest entries beyond the new limit are deleted immediately.

Session isolation: each browser receives a unique session cookie (slotlab-session) on first visit. History is stored under ./history/generate/<sessionId>/ — completely separate for every user.

Expiry: session directories not modified for 7 days are automatically purged by a daily background job.
Reel Set A named logical group of reel strips sharing one restriction configuration. The output JSON array contains one object per reel set with a setName and a reelSet array. Multiple reel sets can be configured to generate different volatility profiles or game modes in a single run.
Reels (Tiles Count) — R1, R2… Each row represents one reel strip. Enter a comma-separated list of non-negative integers where the Nth value is the count of symbol N on that reel. For example, 8, 34, 44, 18 defines a reel containing 8 copies of symbol 1, 34 of symbol 2, 44 of symbol 3, and 18 of symbol 4. The sum of all values is the total reel length.
Restrictions Define the stacking behaviour for reels within a reel set. Restrictions are applied cyclically by reel index: restriction 1 governs R1, restriction 2 governs R2, restriction 1 governs R3 again, and so on. The badge on each restriction header shows exactly which reels it governs. A reel set with no restrictions produces flat (sequential) output regardless of the selected strategy.
stackSizes Comma-separated list of allowed stack heights. A stack is a consecutive run of the same symbol. For example, 1, 2, 3 allows individual tiles, pairs, and triples. All values must be positive integers.
stackChances Percentage weights controlling how often each stack height in stackSizes is selected. Values must be >= 0 and sum to exactly 100. For example, with stackSizes: 1, 2, 3 and stackChances: 60, 30, 10, a height of 1 is chosen 60% of the time. Must have the same length as stackSizes.
minDistance Minimum number of intervening symbols required between two stacks of the same symbol. A value of 1 means no two stacks of the same symbol may be adjacent. A value of 3 requires at least 3 different symbols between them. If this constraint cannot be satisfied after 8 placement attempts, the reel is emitted as [].
Generate — Controls
▶ Run Validates the current configuration, submits it to the backend via POST /api/generate, and writes the resulting JSON reel array to the Result pane. The result is also saved to the history.
✦ Fill / Clear The fastest way to get started. Every reel set card header contains a toggle button that switches between two modes:
Fill — all fields empty → fills tile counts, stack sizes, chances & min distance with placeholder values. Ready to run immediately.Clear — fields have values → button turns red and wipes everything. Reset and start fresh.
Import (↓ button) Opens a dialog to paste the output of a COUNT conversion. The imported data populates the reel sets with the given tile counts. All existing reel sets are replaced. No restrictions are added — configure them manually before running.
+ Add reel set Appends a new reel set card pre-filled with default tile counts and one default restriction.
+ Add reel Appends a new reel row to the reel set. The cyclic restriction mapping recalculates automatically and all restriction badges update to reflect the new reel count.
+ Add restriction Adds a restriction entry to the reel set. Adding more restrictions than there are reels is blocked — additional restrictions would be unreachable due to cyclic mapping.
Session & isolation On your first visit the server sets a cookie named slotlab-session containing a random UUID. All history entries (generate and simulate) are stored under a directory named after that UUID — completely isolated from every other user.

Same session across visits: as long as you don't clear your browser cookies the same UUID is reused, so your history persists between sessions.
Different browsers: each browser has its own cookie store, so Chrome and Safari on the same device get separate histories.
Expiry: session directories that have not been written to for 7 days are automatically deleted by a daily background job. Clearing your cookies abandons your history permanently.
History panel Displays past generation results for your session in reverse chronological order. Clicking an entry restores its output to the Result pane. The Clear history button deletes all your history files from disk. History is private — each user's entries are stored in an isolated directory identified by their session cookie.
Convert — Fields & Controls
Format Output format for the conversion. The input is auto-detected regardless of which format is selected.
COUNT — Reconstructs the per-symbol tile counts from the reel strips (inverse of generation). The output is a JSON array of objects with setName and reelSetTileCounts fields. This output can be pasted directly into the Generate tab via the Import button.
JSON_ARRAY — Reformats the reel data as a JSON array of { setName, reelSet } objects, one entry per reel set. Each reelSet is an array of reel strips represented as integer arrays.
CSV — Emits one row per tile position across all reel strips. Columns: setName, reelIndex (0-based), position (0-based), gameIdTile. Requires the gameId field.
gameId Visible only when Format is CSV. A numeric game identifier that is prepended to the 3-digit zero-padded symbol index to form the gameIdTile column value. For example, gameId = 123 and symbol 1 produce 123001; symbol 42 produces 123042.
Input pane The input format is auto-detected on Run. Two formats are accepted:
JSON array — [{"setName":"…","reelSet":[[…],…]}]. This is the direct output of the Generate tab or a prior JSON_ARRAY conversion.
CSV — The output of a prior CSV conversion. Each row has the form "setName","reelIndex","position","gameIdTile". The symbol index is recovered from the last 3 digits of the gameIdTile value.
▶ Run Detects the input format, parses and validates the data, submits it to the backend via POST /api/convert, and writes the converted result to the Output pane.
Copy (Output pane) Copies the full converted output to the clipboard.
Import / Export — Overview
What this tab does The I/O tab lets you save and restore the entire state of the tool as a single .json file. One export captures all three panels at once: Generate configuration, Simulation (RTP) configuration, and Spin Test configuration — together with the most recent Generate result. Importing the file brings every panel back to exactly the state it was in when you exported.
Export
Preview Builds the export payload from all current form state and displays it in the Export pane so you can inspect or copy it before writing a file. Does not trigger a download. Running Preview again overwrites the previous preview.
Download If a preview is already shown, downloads exactly that text as a .json file (nothing is re-computed). If no preview exists, builds the payload first and then downloads it. The filename is slot-lab-export-YYYY-MM-DDTHH-MM-SS.json.
Export format The exported JSON has three top-level sections:

generate — config holds the reel-set configuration (tile counts, restrictions, strategy, history size); result holds the last generated reel strip array.

simulation — config holds the full RTP simulation configuration: strategy, screen dimensions, symbol table with paytables and wild settings, line definitions, reel-set chances, interval sets.

spinTest — config holds the spin-test settings: reel-set index, stop positions, and a fixed screen if one was entered.

Sections that are empty or invalid at export time are omitted.
Formatting rules The exported JSON is pretty-printed with a set of compaction rules applied so it stays readable without being excessively long:
• Numeric arrays (reel strips, tile counts, stop lists) are collapsed onto a single line each.
• Paytable interval objects {"3": 2.0, "4": 5.0, …} are collapsed to one line.
• Each reel strip inside reelSet is placed on its own line.
• Each reel inside tilesCounts is placed on its own line.
• Line definitions are grouped four per line.
• Restriction objects are collapsed to one line.
Import
How to import Click the drop zone or drag a .json file onto it. The file must be a valid JSON file — any file previously exported from this tool will work. After a successful import the Import pane shows a formatted preview of the loaded data.
What gets restored Generate config — reel sets, tile counts, restrictions, strategy and history size are written back to the Generate tab form.

Generate result — the saved reel strip JSON is placed in the Generate Result pane and the reel-set data becomes available to the Simulation and Spin Test tabs immediately (same effect as clicking Run).

Simulation config — all RTP fields are restored: strategy, screen dimensions, min-match, thread count, bet size, spin count, symbol rows (type, paytable, wild settings), line definitions, reel-set chances, and Megaways height chances if present.

Spin Test config — reel-set index, stop positions, and fixed screen are written back to the Spin Test inputs.

Only sections present in the file are restored; missing sections leave the corresponding tab unchanged.
Importing a raw generate result You can import the raw output of the Generate tab ([{"setName":"…","reelSet":[[…],…]}]) directly — not just full slot-lab export files. The reel data will be loaded into the Generate result pane and will populate the reel-set chances and symbol rows in the Simulation tab, exactly as if you had generated it in this session.
